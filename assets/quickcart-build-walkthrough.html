Not a reference manual — a walkthrough of the actual build order. Every step shows exactly which file gets opened, what goes inside it, and why that piece has to exist before the next one. STEP 4

Open store/models.py

model

This is the first real code of the project — the shape of a "Product" has to exist before anything else (views, cart, admin) can reference it.

store/models.pyreplace contents
from django.db import models

class Category(models.Model):
    name = models.CharField(max_length=100)
    slug = models.SlugField(unique=True)

    class Meta:
        verbose_name_plural = 'categories'

    def __str__(self):
        return self.name


class Product(models.Model):
    category = models.ForeignKey(Category, related_name='products', on_delete=models.CASCADE)
    name = models.CharField(max_length=200)
    slug = models.SlugField(unique=True)
    description = models.TextField(blank=True)
    price = models.DecimalField(max_digits=8, decimal_places=2)
    stock = models.PositiveIntegerField(default=0)
    image = models.ImageField(upload_to='products/', blank=True, null=True)
    available = models.BooleanField(default=True)
    created_at = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return self.name
Why DecimalField, not FloatField, for priceFloating-point numbers introduce rounding errors that are unacceptable for money — DecimalField stores exact values, which matters the moment you start summing a cart.
Why slug on both modelsWe'll use slugs (not numeric IDs) in product URLs later (/products/blue-t-shirt/) — cleaner and more SEO-friendly than /products/17/.

Open store/admin.py

Now that tables exist, we need a way to actually put data into them without writing raw SQL. Django Admin is the fastest path.

store/admin.pyreplace contents
from django.contrib import admin
from .models import Category, Product

@admin.register(Category)
class CategoryAdmin(admin.ModelAdmin):
    list_display = ('name', 'slug')
    prepopulated_fields = {'slug': ('name',)}

@admin.register(Product)
class ProductAdmin(admin.ModelAdmin):
    list_display = ('name', 'category', 'price', 'stock', 'available')
    list_filter = ('available', 'category')
    prepopulated_fields = {'slug': ('name',)}

prepopulated_fields auto-fills the slug from the name as you type in the admin form — one less thing to type by hand for every product.

STEP 8

Open store/views.py

view

Now that real products exist, build the pages that show them.

store/views.pyreplace contents
from django.shortcuts import render, get_object_or_404
from .models import Category, Product

def product_list(request, category_slug=None):
    category = None
    categories = Category.objects.all()
    products = Product.objects.filter(available=True)
    if category_slug:
        category = get_object_or_404(Category, slug=category_slug)
        products = products.filter(category=category)
    return render(request, 'store/product_list.html', {
        'category': category,
        'categories': categories,
        'products': products,
    })

def product_detail(request, slug):
    product = get_object_or_404(Product, slug=slug, available=True)
    return render(request, 'store/product_detail.html', {'product': product})
Why get_object_or_404 here specificallyA mistyped or old product URL should show a clean 404, not crash the whole page with an unhandled DoesNotExist traceback in front of a real customer.

cart/cart.pynew file — session engine
from decimal import Decimal
from django.conf import settings
from store.models import Product

class Cart:
    def __init__(self, request):
        self.session = request.session
        cart = self.session.get('cart')
        if not cart:
            cart = self.session['cart'] = {}
        self.cart = cart

    def add(self, product, quantity=1):
        product_id = str(product.id)
        if product_id not in self.cart:
            self.cart[product_id] = {'quantity': 0, 'price': str(product.price)}
        self.cart[product_id]['quantity'] += quantity
        self.save()

    def save(self):
        self.session.modified = True

    def remove(self, product):
        product_id = str(product.id)
        if product_id in self.cart:
            del self.cart[product_id]
            self.save()

    def __iter__(self):
        product_ids = self.cart.keys()
        products = Product.objects.filter(id__in=product_ids)
        for product in products:
            item = self.cart[str(product.id)].copy()
            item['product'] = product
            item['price'] = Decimal(item['price'])
            item['total_price'] = item['price'] * item['quantity']
            yield item

    def __len__(self):
        return sum(item['quantity'] for item in self.cart.values())

    def get_total_price(self):
        return sum(Decimal(item['price']) * item['quantity'] for item in self.cart.values())

    def clear(self):
        del self.session['cart']
        self.save()
Why a plain Python class here, not a Django modelThe cart is temporary per-visitor state, not permanent business data — storing it in the session (not the database) means an anonymous visitor gets a working cart with zero extra tables, and it naturally clears itself when their session ends.
cart/views.pynew
from django.shortcuts import render, redirect, get_object_or_404
from django.views.decorators.http import require_POST
from store.models import Product
from .cart import Cart

@require_POST
def cart_add(request, product_id):
    cart = Cart(request)
    product = get_object_or_404(Product, id=product_id)
    quantity = int(request.POST.get('quantity', 1))
    cart.add(product=product, quantity=quantity)
    return redirect('cart:cart_detail')

@require_POST
def cart_remove(request, product_id):
    cart = Cart(request)
    product = get_object_or_404(Product, id=product_id)
    cart.remove(product)
    return redirect('cart:cart_detail')

def cart_detail(request):
    cart = Cart(request)
    return render(request, 'cart/cart_detail.html', {'cart': cart})

@require_POST on cart_add/cart_remove: mutating actions should never respond to a plain GET link.

def checkout(request):
    cart = Cart(request)
    if len(cart) == 0:
        return redirect('cart:cart_detail')
    if request.method == 'POST':
        # Real payment processing would go here.
        # For this simple project, we just clear the cart and show a confirmation.
        cart.clear()
        return render(request, 'cart/checkout_success.html')
    return render(request, 'cart/checkout.html', {'cart': cart})

The pattern worth remembering

The build order was never random.

Model→ Migrate→ Admin (seed data)→ View→ URL→ Template

It followed one repeating loop, and whenever a template referenced something that didn't exist yet (cart:cart_add, cart:checkout), that became the very next thing built. That's the real habit this walkthrough is teaching: build the layer that has nothing to depend on first (the data shape), and let each following file's requirements pull the next file into existence — rather than trying to plan every file up front.
