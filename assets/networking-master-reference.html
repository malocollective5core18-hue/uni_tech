Part 1 — Fundamentals

01 The boxes on the network

Titles get used loosely in the field. A "router" people hand you is often doing three or four jobs at once. Separating the jobs makes any device's settings page make sense immediately.

Layer 1–2

Modem

Translates the ISP's signal (fibre, coax, cellular) into Ethernet. Doesn't route, doesn't do Wi-Fi, doesn't assign local addresses. One WAN connection in, one Ethernet port out.

Layer 3

Router

Sits between two networks (your LAN and the ISP's WAN) and decides how traffic moves between them. Runs NAT, usually runs DHCP, usually has a firewall.

Layer 2

Switch

Joins wired devices on the same network. No routing, no NAT, no DHCP of its own. Just extends the number of wired ports.

Layer 2

Access Point (AP)

The wireless equivalent of a switch: extends an existing network over radio. Doesn't create a new network, doesn't route, doesn't (normally) run DHCP.

Layer 2

Repeater / Extender

Rebroadcasts an existing wireless signal further, over the air, usually at reduced throughput because it must receive and resend on the same radio.

System

Mesh node

A repeater with a brain: multiple nodes coordinate, use a dedicated backhaul channel where possible, and hand devices between nodes automatically.

The one-liner that matters most A consumer "router" is a router + switch + AP + firewall in one box. When you put a second one on the network purely for Wi-Fi coverage, you want the switch+AP half only — which is exactly what "run it as an AP" means, even when the device has no AP mode in its firmware.

02 Operation modes explained

"Operation Mode" pages vary a lot between vendors and even between models from the same vendor. Some spell out Access Point as a menu option; others don't have the concept at all and you build it manually. Know the underlying scenario, not the label.

ScenarioWhat it meansHow it's usually built
RouterCreates a new LAN, does NAT between it and the WAN, hands out addresses.WAN port connected to modem/ISP, DHCP server on — the default state of most routers out of the box.
Access PointExtends an existing LAN over Wi-Fi. No new subnet, no second NAT layer.Uplink into a LAN port (not WAN), DHCP server off, static LAN IP in the host network's range.
Bridge / WDSWirelessly joins two access points into one Layer-2 network, extending a LAN without a cable run.Both ends configured with each other's SSID/MAC under WDS settings. Throughput is shared across the link.
RepeaterReceives and rebroadcasts an existing SSID to widen coverage.Associates to the parent SSID as a client, then rebroadcasts it. Same subnet, no new DHCP scope.

Manufacturer language for the "Access Point" scenario varies: "AP Mode," "Wireless Bridge," "Wireless Ethernet Client," or no explicit mode at all — just a manual DHCP-off plus LAN-uplink configuration.

03 IP addressing & DHCP

Almost every home-network problem — devices that "can't see each other," a second router that "breaks" the internet, a static device that stops responding after a reboot — traces back to addressing.

Private address ranges (RFC 1918)

RangeSizeTypical use
10.0.0.0 – 10.255.255.25516.7M addressesLarge or segmented business networks
172.16.0.0 – 172.31.255.2551M addressesMid-size networks, common in enterprise gear defaults
192.168.0.0 – 192.168.255.25565K addressesHome and small-office routers

How DHCP actually works — DORA

// A device joining the network, in order 1. DISCOVER — client broadcasts "is there a DHCP server here?" 2. OFFER — server proposes an address + lease time 3. REQUEST — client asks to actually use that address 4. ACK — server confirms; client configures itself

This is exactly why two DHCP servers on one network cause chaos: two OFFERs can arrive for the same broadcast, and different devices end up with addresses assigned by different authorities that don't agree on gateway or DNS.

Field symptom to remember Intermittent connectivity that "fixes itself on reboot," duplicate IP warnings, or some devices reaching the internet while others on the same Wi-Fi can't — check for a second live DHCP server before anything else.

Static vs. reserved vs. dynamic

  • Dynamic — DHCP assigns it, can change on lease renewal. Fine for phones, laptops, guests.
  • Reserved — still handed out by DHCP, but the server always gives the same address to that MAC. Best practice for printers, cameras, and anything a firewall rule points at.
  • Static — set by hand on the device itself, outside DHCP's control entirely. Necessary for an AP's own management address once its own DHCP server is disabled.

04 NAT, port forwarding & DMZ

These three sit together because they all answer the same question in different ways: how does something outside the LAN reach something inside it?

NAT (Network Address Translation)

Lets many private LAN addresses share one public IP by rewriting the source address of outgoing packets and tracking the mapping to route replies back correctly. This is also why a home LAN is invisible from the outside by default — unsolicited inbound traffic has no mapping to follow, so it's dropped.

Port forwarding / virtual servers

A deliberate hole punched in that default-closed behavior: traffic to the router's public IP on a specific port gets forwarded to one specific internal host and port.

DMZ host

The blunt version of port forwarding — all unmatched inbound ports go to one internal host, unfiltered. That host loses the router's protection entirely, so it should never be a general-purpose PC.

UPnP

Lets applications open their own port forwards automatically. Convenient, but it means any device or piece of malware on the LAN can ask the router to open a hole.

Rule of thumb Port forward the specific port a specific service needs. Reach for DMZ only for isolated test/lab hosts, and never leave UPnP on for a network you don't control end to end.

05 Wireless fundamentals

The physics and the standards behind every "which band," "which channel," "which mode" decision on a wireless settings page.

802.11 standards

StandardMarketing nameBand(s)Practical note
802.11b—2.4 GHzLegacy; slows every network it joins if still allowed
802.11g—2.4 GHzUp to 54 Mbps; still common as a compatibility floor
802.11nWi-Fi 42.4 & 5 GHzIntroduced MIMO
802.11acWi-Fi 55 GHzWide channels, higher throughput, less legacy baggage
802.11axWi-Fi 6 / 6E2.4, 5, 6 GHzOFDMA improves performance with many simultaneous clients

2.4 GHz vs. 5 GHz vs. 6 GHz

2.4 GHz

Longest range and best wall penetration, but only 3 non-overlapping channels (1, 6, 11) and heavy contention.

5 GHz

Far more non-overlapping channels, higher throughput, shorter range and worse wall penetration.

6 GHz (Wi-Fi 6E/7)

Wide-open spectrum with far less legacy interference, but the shortest range of the three.

Channel width

Wider channels (40/80/160 MHz vs. 20 MHz) move more data per unit time but occupy more spectrum and overlap more with neighboring networks. In dense environments, narrower channels with less overlap often outperform wide ones on paper-spec throughput.

SSID broadcast & hidden networks

Disabling SSID broadcast stops the name appearing in a casual scan, but it is not a security control — the SSID is still sent in cleartext when a known client tries to connect. Treat it as air-traffic tidiness, not protection.

06 Wireless security

The list every client and every audit will ask about. Know which protocols are obsolete and why.

ProtocolStatusNotes
Open / no securitySituationalCorrect only for a deliberately public network — never for anything with private traffic behind it.
WEPBrokenCrackable in minutes with freely available tools. Never deploy.
WPA / WPA-Personal (TKIP)DeprecatedSuperseded by WPA2; keep only if a legacy device truly requires it.
WPA2-Personal (AES)Current baselinePre-shared key, shared by everyone on the network — a reasonable minimum today.
WPA2/WPA3-EnterpriseBusiness standardEvery user authenticates individually against a RADIUS server — no shared password to leak.
WPA3-PersonalCurrent best (home/SMB)Resistant to offline dictionary attacks against a captured handshake, which WPA2-Personal is not.

Personal vs. Enterprise, in plain terms

Personal mode means one password for every device. Enterprise mode means every person logs in with their own credentials against a RADIUS/AAA server — higher setup cost, but a departing employee's access can be revoked without touching anyone else's.

WPS

Designed to simplify pairing, but the PIN method has a well-known brute-force weakness. Leave it off on anything internet-facing or physically reachable by the public.

07 Segmentation & isolation

The difference between "everyone shares one flat network" and "traffic only goes where it needs to" — the single biggest lever for both security and troubleshooting sanity.

VLANs

A VLAN splits one physical network into multiple logical ones — devices on VLAN 10 can't see VLAN 20 traffic even though they share the same switch, unless a router explicitly permits it.

Guest networks

A separate SSID mapped to its own VLAN/subnet with no route back to the main LAN.

AP Isolation

Within a single wireless network, stops client devices from talking directly to each other. Non-negotiable on any open or public SSID.

Mental model VLANs separate networks from each other. AP Isolation separates devices from each other within the same network. A public Wi-Fi deployment usually wants both.

08 Firewall & threat basics

What the toggles under "Security" are actually defending against.

SPI (Stateful Packet Inspection)

Tracks connection state and only allows inbound traffic that's a legitimate reply to something the LAN initiated.

DoS / flood filtering

Watches for abnormal volumes of SYN, UDP, or ICMP packets in a short window and starts blocking the source.

VPN passthrough

PPTP/L2TP/IPSec passthrough lets VPN tunnels traverse a NAT router correctly.

Access control vs. parental control

Functionally similar under the hood — both build a rule from a host, a target, and a schedule — but framed differently as security policy vs. time/content management.

09 Deploying public Wi-Fi

Turning off the password is the easy 10% of a public hotspot. This is the other 90%.

Open vs. captive portal

A fully open SSID is simplest to deploy but has no acceptance-of-terms step and no way to differentiate users. A captive portal adds a landing page users must interact with before getting online.

Isolation is not optional

On an open network, any two connected strangers can otherwise see each other's file shares and sometimes intercept traffic. AP Isolation must be on, and any nearby private network needs a separate subnet/VLAN with no route to it.

Bandwidth control

An unmanaged public SSID lets one device starve everyone else. Per-client or per-rule bandwidth caps keep the hotspot usable under load.

Logging & liability

Operators of public internet access may have retention obligations, or at least a strong practical interest in keeping connection logs. This is legal/policy territory worth flagging to ownership rather than deciding unilaterally.

What to tell a client who says "just make it open" Open is fine as the authentication model. It is not an excuse to skip AP isolation, network segregation, and a bandwidth policy.

10 Admin access & hardening

The settings that protect the router itself, independent of anything it's serving to clients.

  • Change default admin credentials — "admin/admin" is the first thing any scanner tries.
  • Disable remote management unless specifically needed; if it must stay on, restrict it to a source IP and change the default port.
  • Restrict local management by MAC where supported.
  • Keep firmware current — updates are disproportionately security patches.
  • Turn off services you're not using — UPnP, WPS, USB sharing, remote management.
  • Set DNS deliberately, not by accident — DNS redirection is a common attack surface on compromised routers.

Questions to settle before configuring anything

  • Does the bus stand's public Wi-Fi need to reach the same internet uplink as the school, or is it better as its own independent connection?
  • Is the software your clients use hosted centrally (needs routing back to a central server) or per-site (each location is self-contained)?
  • Do school staff/admin networks need to stay isolated from student and public-facing networks? In almost every case: yes.
A pattern worth adopting as policy Treat "the school network" and "the bus stand public network" as separate logical networks that happen to share infrastructure — not as one flat LAN. Segment first, then decide what's allowed to cross between them.

13 Wireless backhaul between sites

Bus stands rarely have convenient fiber runs. This is where MikroTik's PtP (point-to-point) and PtMP (point-to-multipoint) wireless gear earns its keep.

1:1

Point-to-Point

One dedicated link between two fixed locations. Highest throughput and most predictable performance per link.

1:many

Point-to-Multipoint

One base station serves several remote sites at once. More efficient hardware use, but shared bandwidth across all of them.

Practical siting concerns

  • Line of sight — trees, buildings, and seasonal foliage growth can degrade a link that tested fine at install.
  • Fresnel zone clearance — visual line of sight isn't enough if the calculated Fresnel zone is obstructed.
  • Frequency choice — 5 GHz is license-exempt in most regions but faces more contention; licensed bands or 60 GHz suit tight, high-value links.
  • Power & mounting — bus stand infrastructure often has weaker power and less secure mounting than a school building.
Common failure mode A backhaul link aligned and tested once, then never revisited. Wind, thermal expansion, and nesting birds shift alignment over months — build periodic link-health checks into your maintenance schedule.

14 CAPsMAN — managing many APs centrally

CAPsMAN (Controlled Access Point system Manager) turns "a pile of individually configured access points" into "one wireless network you manage from one place." The single highest-leverage MikroTik feature for a deployment with this many APs.

How it works, conceptually

  • One device (or a redundant pair) runs the CAPsMAN manager role — holding the actual SSID, security, and channel configuration.
  • Every physical access point runs in CAP (Controlled Access Point) mode — fetching its settings from the manager instead of holding its own.
  • Change the SSID password once on the manager, and every CAP across every building and bus stand picks it up.

Why this matters specifically for your topology

Seamless roaming is the practical payoff: a device moving from inside the school building to the bus stand outside can hand off between APs on the same SSID without dropping, because CAPsMAN coordinates channel and client information across all of them.

Manager placement The CAPsMAN manager role can live on the core router itself for a small deployment, or on a dedicated device once you're managing dozens of APs across many sites.

15 Addressing & VLANs at scale

The private-address and DHCP fundamentals from Part 1 still apply — the difference is you're now planning address space for multiple sites and traffic types deliberately, not just avoiding one collision.

A workable subnet pattern

# Illustrative scheme only — adapt to your actual scale 10.10.0.0/16 → whole deployment, one school district 10.10.1.0/24 → school admin/staff VLAN 10.10.2.0/24 → school student/lab VLAN 10.10.10.0/24 → public Wi-Fi, bus stand A 10.10.11.0/24 → public Wi-Fi, bus stand B 10.10.99.0/24 → management VLAN (router/AP admin interfaces only)

The third octet becomes "which site/purpose," making a stray IP in a log immediately meaningful — worth enforcing across your whole tech team rather than letting each install improvise its own scheme.

A dedicated management VLAN

Put every router and AP's own admin interface on a VLAN that ordinary client traffic can never reach, so a compromised device on the public Wi-Fi has no path to even attempt logging into your infrastructure.

16 Hotspot / captive portal for public access

This is the piece consumer routers simply don't have, and it's usually exactly what a bus stand's public Wi-Fi needs: a proper login/landing page rather than a bare open SSID.

What MikroTik's Hotspot feature gives you

  • A walled-garden landing page shown before internet access is granted — terms of use, a login form, or a voucher code entry.
  • Per-user or per-voucher time and data limits.
  • Built-in user management — vouchers can be generated in batches rather than a single shared password.
  • A walled garden list of sites reachable without logging in — useful for your own client software's login/health-check endpoints.

Where this connects back to your client software

If your software authenticates or phones home before a user should get broader internet access, the walled garden list is exactly the mechanism to let that specific traffic through pre-login. Worth documenting the exact hostnames/IPs it needs so every site's config is consistent.

17 Bandwidth management

A single school building can absorb a lot of simultaneous streaming before anyone notices. A bus stand serving a queue of riders on shared backhaul cannot.

ToolBest for
Simple QueueQuick per-IP or per-subnet caps — e.g. "the bus stand subnet gets no more than X Mbps."
Queue Tree + PCQFair, automatic per-user sharing — PCQ dynamically splits available bandwidth among however many active users there are at that moment.

For a public hotspot with an unpredictable number of simultaneous users, PCQ is usually the right tool: it doesn't require knowing in advance how many devices will be connected.

Protect the uplink, not just the client Even with per-user fairness inside a subnet, cap the subnet's total consumption against the site's actual uplink capacity, or a fully-loaded bus stand can still saturate a shared backhaul link and degrade the school's own traffic.

18 Firewall & segmentation at scale

The same SPI/NAT/DMZ concepts from Part 1 apply, but at this scale the firewall's real job is enforcing which of your VLANs can talk to which — not just protecting the LAN from the internet.

  • Default-deny between VLANs — explicitly allow only the specific traffic that needs to cross, rather than allowing everything and blocking exceptions.
  • Address lists — group related subnets (all bus-stand subnets, all school-admin subnets) so rules stay readable as you add more sites.
  • Management-plane protection — restrict who can reach RouterOS's own services (Winbox, API, SSH) by source address/VLAN, on every device.
  • Logging on drop rules — sample-log denied cross-VLAN attempts; often the first sign of a misconfigured device or an intrusion attempt.

19 Monitoring a distributed network

Once you have more than two or three sites, "wait for someone to complain" stops being an acceptable monitoring strategy.

Link health

Signal strength, CCQ, and throughput on every wireless backhaul link, tracked over time.

Device reachability

Basic up/down monitoring for every router and AP across every site.

Capacity trends

Bandwidth usage per site over weeks/months shows which site is outgrowing its current link.

For a team of techs, a shared monitoring dashboard also gives you, as manager, a way to see the state of the whole deployment without relying on each tech's individual memory of how a given site is doing.

20 Deployment checklists

Two checklists — general practice for any router/AP job, and MikroTik-specific rollout for a new site.

General router / AP deployment

  • Confirmed whether the box is acting as router, AP, bridge, repeater, or WISP client — and configured the matching WAN/LAN/DHCP state, not just the label
  • Exactly one DHCP server active on the network segment
  • Static/reserved addressing on management interfaces and anything a firewall rule points at
  • WPA2-Personal (AES) minimum, WPA3 where supported — never WEP, never open unless deliberately public
  • AP Isolation on for any open or public SSID
  • Default admin credentials changed; remote management off or restricted
  • WPS off unless actively needed that day; firmware checked and current

MikroTik multi-site rollout

  • Site added to the addressing plan with its own consistent subnet(s) before any hardware is configured
  • Management VLAN configured and confirmed unreachable from client-facing VLANs
  • CAPsMAN CAP mode applied to every AP at the site — no AP left in standalone config
  • Backhaul link tested for both signal quality and actual throughput, not just "connected"
  • Hotspot walled garden includes every hostname/IP your client software needs pre-login
  • PCQ or equivalent bandwidth fairness applied to any shared public subnet
  • Cross-VLAN firewall rules follow default-deny, with only required exceptions added
  • Device added to the monitoring system before the crew leaves site
  • Site documented — diagram, subnet list, device inventory — in the team's shared system

21 Glossary

AP Isolation
Prevents wireless clients on the same SSID from communicating directly with each other.
CAP
Controlled Access Point — an AP running in managed mode, taking its configuration from a CAPsMAN manager rather than holding its own.
CAPsMAN
Controlled Access Point system Manager — MikroTik's centralized wireless management system for configuring and coordinating many APs from one place.
CCQ
Client Connection Quality — a MikroTik wireless metric estimating how efficiently a link is using available airtime, useful for spotting a degrading backhaul link.
DHCP
Dynamic Host Configuration Protocol — automatically assigns IP addresses and network parameters to devices joining a network.
DMZ (host)
A LAN host exposed to all unmatched inbound traffic from the WAN, bypassing normal firewall filtering.
DNS
Domain Name System — resolves human-readable names (example.com) to IP addresses.
Fresnel zone
The three-dimensional region around the direct line between two wireless antennas that must be substantially clear of obstructions for the link to perform at its rated capacity.
Hotspot (MikroTik)
RouterOS's built-in captive-portal feature: intercepts new connections with a login/terms page before granting broader internet access.
MAC address
A hardware address burned into a network interface, used for addressing at Layer 2 (as opposed to an IP address at Layer 3).
MTU
Maximum Transmission Unit — the largest packet size a network link will carry without fragmenting it.
NAT
Network Address Translation — rewrites private addresses to a shared public one (and back) so many devices can share one internet connection.
PCQ
Per Connection Queue — a queuing method that automatically and fairly splits available bandwidth among however many active connections exist, without pre-configuring a fixed number of users.
PtP / PtMP
Point-to-Point / Point-to-Multipoint — wireless link topologies for connecting one site to another (PtP) or one base station to several remote sites at once (PtMP).
RADIUS
A protocol for centralized authentication — the backbone of WPA-Enterprise, where each user has individual login credentials instead of a shared password.
RouterOS
MikroTik's operating system, running on hardware from small home routers up to core-grade routers, unified under one configuration model.
SPI Firewall
Stateful Packet Inspection — tracks connection state so only legitimate replies to outbound traffic are allowed back in.
SSID
Service Set Identifier — the human-readable name of a wireless network.
The Dude
MikroTik's free network monitoring and mapping tool.
UPnP
Universal Plug and Play — lets applications automatically open their own port forwards on the router.
VLAN
Virtual LAN — logically separates one physical network into multiple isolated broadcast domains.
Walled garden
A list of destinations a hotspot user can reach without first completing login/authentication — used for a client's own pre-login endpoints, terms pages, or payment gateways.
WDS
Wireless Distribution System — lets access points bridge to each other over Wi-Fi to extend a LAN without cabling.
Winbox
MikroTik's native desktop configuration utility, able to connect via MAC address even before a device has a usable IP.
WISP client mode
A router mode where its uplink to the internet is itself a Wi-Fi connection to someone else's network, rather than a wired WAN.
WPS
Wi-Fi Protected Setup — a simplified pairing method (push-button or PIN) with a known PIN-brute-force weakness.
