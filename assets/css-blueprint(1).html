Margin · Lab 1/3

Uniform margin — one value, every side

A single margin value applies to all four sides equally. Margin pushes other elements away — it doesn't grow the target box itself, it grows the empty space around it. Watch both siblings move away from the target equally as you increase the value.

Margin · Lab 3/3
Special values — auto, negative, percentage

        
margin: auto on a block element with a set width centers it horizontally. A negative margin pulls the element (and can overlap a neighbor) instead of pushing it away. A percentage margin — on any side, including top/bottom — is always calculated from the container's width, never its height or the element's own size.

Do
    
          
  • Use margin: auto to horizontally center a block element that has an explicit width.
    • 
          
  • Reach for a negative margin deliberately, when you want one element to visually overlap a specific neighbor.
    • 
          
  • Remember vertical margins between block siblings collapse to the larger one — they don't add together.
    • 
        

        
Don't
    
          
  • Don't expect a percentage margin-top/margin-bottom to relate to the element's height — it's always a percentage of the container's width.
    • 
          
  • Don't use margin when you actually want to grow the box itself — that's padding's job, not margin's.

Padding · Lab 1/3
Uniform padding — one value, every side

        
Padding is the cushion inside the border, between the border and the content. Unlike margin, it doesn't push siblings away — with the default box-sizing:content-box it makes the rendered box itself bigger. Padding · Lab 2/3
Per-side padding — four independent values

        
Same idea as margin's per-side controls, but padding pushes the content inside the box instead of the neighbors outside it. In a fixed-size box, growing one side's padding visibly shoves the centered content toward the opposite side.

Padding · Lab 3/3
Special values — percentage, em, and the aspect-ratio trick

        
A percentage padding — on every side, top/bottom included — is calculated from the container's width. An em padding scales with the element's own font-size. And the classic trick: a padding-bottom percentage on an empty box was the pre-aspect-ratio way to force a fixed width/height ratio (like 56.25% for 16:9 video embeds).

—

          

        

        

          

          

        

      


      

        
Do
    
          
  • Use box-sizing:border-box (see Module 01) so padding doesn't silently grow your declared width.
    • 
          
  • Use a percentage padding-bottom trick — or better, the modern aspect-ratio property — to keep embeds at a fixed ratio.
    • 
          
  • Use em padding when you want a component's spacing to scale automatically with its own text size.
    • 
        

        
Don't
    
          
  • Don't forget percentage padding on any side is relative to the container's width, including padding-top/padding-bottom — a very common surprise.
    • 
          
  • Don't add padding to shove content away from a border when what you actually want is space between this box and its neighbor — that's margin's job.
    • 
        

      

    


    
    

      
01
The Box Model

      
Every element is content → padding → border → margin, from the inside out. box-sizing decides whether width/height measure the content alone, or the content plus padding and border.


      

        

        

          

            
content box

            
Rendered size: —

          

        

      


      

        

        

      


      

        
Do
    
          
  • Set *{box-sizing:border-box} globally, once, project-wide.
    • 
          
  • Use border-box so a declared width stays the actual rendered width no matter what padding/border you add later.
    • 
          
  • Reach for negative margins deliberately to pull an element toward a neighbor.
    • 
        

        
Don't
    
          
  • Don't mix content-box math into a layout by accident — it's the #1 cause of "why is this 32px too wide."
    • 
          
  • Don't assume two stacked vertical margins add — block siblings collapse to the larger one, not the sum.
    • 
          
  • Don't forget margin collapsing stops inside flex/grid containers — items there never collapse margins.
    • 
        

      

    


    
    

      
02
Display Types

      
Before Flexbox/Grid, every element defaults to block, inline, or inline-block — this trio explains most "why won't this sit next to that" bugs.


      

        

        

          

            

              
Text flows in before the target and continues right after it, so you can see exactly how it behaves in a real sentence.

            

            
—

          

        

      


      

        

        

      


      

        
Do
    
          
  • Use inline-block (or better, flex/grid) when you need a row of boxes that still respect width/height/padding.
    • 
          
  • Use display:none to fully remove something from layout and the accessibility tree.
    • 
        

        
Don't
    
          
  • Don't set width/height on an inline element expecting it to apply — it's silently ignored.
    • 
          
  • Don't confuse display:none (removes layout space) with visibility:hidden (invisible but still occupies space).
    • 
          
  • Don't write inline-block elements across multiple HTML lines without noticing the "phantom whitespace" gap that appears between them.
    • 
        

      

    


    
    

      
03
Flexbox

      
Flexbox is a two-piece system: nothing below works until the parent has display:flex — every other property here is inert without it. Once that's set, parent properties (justify-* for the main axis, align-* for the cross axis) arrange all children at once, and a handful of child properties (flex-grow, align-self, order) let one item break away from the group. The labs below build up in that order: turn flex on, isolate the two axis properties, then layer in wrapping, sizing, and reordering.

Flexbox · Lab 5/6
flex-grow, flex-shrink & flex-basis — child sizing

        
These three control how one child's size compares to its siblings, independent of alignment. flex-basis is the starting size before growing/shrinking; flex-grow is how eagerly it claims leftover space; flex-shrink is how eagerly it gives space up when there isn't enough. Change child B's values and watch it claim (or give up) space relative to A and C, which stay at flex: 1 1 0.

Flexbox · Lab 6/6
order — visual reordering without touching the HTML

        
Every flex item defaults to order:0 and displays in source order. Give one item a different order value and it moves purely visually — screen readers and keyboard tab order still follow the original HTML, which is why order should only be used for cosmetic reshuffling, not to fix a real content-order problem.

Do
    
          
  • Set display:flex (or inline-flex) first — every other flex property is a no-op without it.
    • 
          
  • Use gap for spacing between flex items instead of margin hacks.
    • 
          
  • Use align-self on one item when everything else should follow align-items.
    • 
          
  • Remember align-items:stretch is the default — children with no set height already stretch to fill the cross axis.
    • 
        

        
Don't
    
          
  • Don't reach for align-content expecting it to do anything with flex-wrap:nowrap — it only affects multiple wrapped lines.
    • 
          
  • Don't confuse flex-basis:0% (equal columns, ignores content) with auto (content-weighted columns) — this is why flex:1 and flex:1 1 auto render differently.
    • 
          
  • Don't use order to fix content that's in the wrong place in the HTML — it only changes visual order, not reading or tab order.
    • 
        

      

    


    
    

      
04
CSS Grid

      
Like Flexbox, nothing below works until the parent has display:grid. From there, grid-template-columns/-rows define the explicit tracks; gap spaces them; justify-items/align-items position everything inside its cell by default, and any single item can override with justify-self/align-self — a concept Flexbox doesn't have. The labs below isolate each piece before combining them all.

gap is shorthand for row-gap column-gap — space between cells only, never around the outer edge. That's the key difference from margin: no matter how large the gap, the grid never grows padding on its own boundary.

Do
    
          
  • Set display:grid first — every other grid property is a no-op without it.
    • 
          
  • Use repeat(auto-fit, minmax(160px,1fr)) for a responsive grid with zero media queries — try it in the dropdown above.
    • 
          
  • Set grid-auto-rows explicitly when items can overflow your template — otherwise implicit rows default to auto and can look inconsistent in height.
    • 
        

        
Don't
    
          
  • Don't confuse auto-fill (keeps empty tracks, leaves gaps) with auto-fit (collapses empty tracks, items stretch) — compare them directly with the grid-template-columns dropdown.
    • 
          
  • Don't forget dense packing (in grid-auto-flow) can visually reorder items away from source/DOM order — an accessibility trade-off, not a free win.
    • 
          
  • Don't reach for margin to space out grid cells — gap handles it without adding space around the grid's own outer edge.
