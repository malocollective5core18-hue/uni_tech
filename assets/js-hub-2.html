Variables & data types

The nouns of the language — how you hold a value, and the handful of types every value belongs to.

let vs. const vs. var

const can't be reassigned. let can. var is the old way — avoid it in new code.

js

The primitive types

typeof tells you exactly what kind of value you're holding — the first tool for debugging weird behavior.

js

Template literals

Backticks let you embed variables directly in a string — no more string concatenation with +.

js

Type coercion surprises

== converts types before comparing; === does not. This single difference prevents a huge class of bugs.

js

Numbers: NaN and Infinity

JavaScript has exactly one number type — but it has some famous edge-case values worth knowing by sight.

js

Truthy and falsy values

Every value is either truthy or falsy when used in a condition — only eight values are actually falsy.

02

Operators & expressions

The small symbols that combine values into new ones — arithmetic, comparison, and logic.

Arithmetic operators

The usual six, plus ** for exponents — no separate power() function needed.

js

Comparison operators

Prefer === and !== almost always — they're predictable in a way == and != aren't.

js

Logical operators & short-circuiting

&& stops at the first falsy value; || stops at the first truthy one — used constantly for defaults.

js

The ternary operator

A one-line if/else that returns a value — perfect for a quick either/or decision.

js

Nullish coalescing (??) vs. OR (||)

?? only falls back on null/undefined — || falls back on ANY falsy value, including 0 and "", which is often wrong.

js

Optional chaining (?.)

Safely read a nested property that might not exist, without a crash or a manual check first.

03

Control flow

How a program decides what to do next, and how to repeat an action without copy-pasting it.

if / else if / else

Checked top to bottom — the first true condition wins, the rest are skipped.

js

switch

Cleaner than a long if/else chain when you're comparing one value against many exact options.

js

for loop

The classic three-part loop — init, condition, and what runs after each pass.

js

while / do...while

while checks first, do...while runs once before checking — a subtle but real difference.

js

for...of vs. for...in

for...of iterates VALUES (arrays, strings); for...in iterates KEYS (object properties). Mixing them up is a classic bug.

js

break and continue

break exits the loop entirely. continue skips just this iteration and moves to the next.

js
04

Functions

Packaging logic so you write it once and reuse it — the single most important habit for clean code.

Declaration vs. expression

A function declaration is hoisted (usable before its definition); a function expression is not.

js

Arrow functions

Shorter syntax, and — importantly — no own `this`, which fixes a common bug from regular functions in callbacks.

js

Default parameters

A fallback value used only when the argument is omitted or undefined — no manual `if` needed inside the function.

js

Rest parameters (...args)

Collects any number of extra arguments into a real array — no more juggling the old `arguments` object.

js

Closures

An inner function remembers the variables from where it was created, even after the outer function has finished running.

js

IIFE — Immediately Invoked Function Expression

A function that runs itself once, right away — useful for isolating variables from the surrounding scope.

js
05

Arrays

Ordered lists of values, and the handful of built-in methods that cover almost everything you'll ever do with them.

Creating & accessing arrays

Zero-indexed — the first item is index 0, and .length always tells you how many there are.

js

push / pop / shift / unshift

Add or remove from either end — push/pop work at the end, shift/unshift work at the start.

js

map() — transform every item

Returns a brand NEW array — the original is never changed.

js

filter() — keep only some items

Returns a new array with only the items where the function returned true.

js

reduce() — combine into one value

The most flexible array method — sums, builds objects, flattens arrays, all with the same shape.

js

find / some / every

find returns the first match. some checks if ANY item matches. every checks if ALL items match.

js
06

Objects

Labeled data — the shape behind almost every real piece of information: a user, a config, an API response.

Object literals & access

Dot notation for known keys, bracket notation when the key is a variable or has special characters.

js

Destructuring

Pull properties out into their own variables in one line, instead of one assignment per property.

js

The spread operator ({...obj})

Copies an object's properties into a new one — the standard way to update state immutably.

js

Object.keys / values / entries

Three ways to loop over an object's contents, depending on what you actually need.

js

Computed property names

Use a variable's VALUE as a key name, built dynamically instead of typed literally.

js

Methods & this

A function stored as an object property — `this` inside it refers to the object it was called on.

js
07

Strings

Text manipulation — the methods you'll reach for constantly when cleaning up or formatting real data.

Template literals with expressions

Any JavaScript expression works inside ${ } — not just variables.

js

slice / substring

Extract part of a string by index — negative numbers count from the end.

js

split / join

split turns a string into an array; join turns an array back into a string — often used together.

js

includes / startsWith / endsWith

Readable substring checks — no more manual indexOf() !== -1 comparisons.

js

replace / replaceAll

replace changes the first match; replaceAll changes every match — a common source of subtle bugs when confused.

js

trim / padStart / padEnd

Clean up whitespace, or pad a string to a fixed width — handy for aligning output or formatting IDs.

08

The DOM

Turning JavaScript loose on an actual web page. Each example below gets its own live mini-page to work on — safe to experiment with, changes nothing outside the box. Sixteen examples here — this is the part that matters most for real web work.

querySelector / querySelectorAll

querySelector returns the first match; querySelectorAll returns ALL matches, as a static list.

js

textContent vs. innerHTML

textContent treats everything as plain text. innerHTML parses it as real markup — a difference that also matters for security.

js

classList — add / remove / toggle

The clean way to control CSS classes from JS, instead of string-editing className by hand.

js

Creating & appending elements

Build a new element with createElement, then attach it to the page with appendChild.

js

Changing styles via JS

element.style.property directly sets inline CSS — useful for one-off, dynamic changes.

js

Removing elements

element.remove() takes it out of the page entirely — no parent lookup required, unlike the old removeChild approach.

js

getElementById vs. getElementsByClassName

getElementById only exists on `document` itself, never on another element — getElementsByClassName works on any node and returns a LIVE list.

js

setAttribute / getAttribute / removeAttribute

The general-purpose way to read or write ANY HTML attribute, not just the common ones with their own shortcut property.

js

dataset — reading data-* attributes

Every data-my-thing attribute becomes element.dataset.myThing automatically — camelCase, no manual parsing.

js

cloneNode — duplicating an element

cloneNode(true) copies an element AND everything inside it — the standard way to stamp out repeated UI from one template.

js

insertAdjacentHTML — precise positioning

Insert markup at an exact position relative to an element, without rebuilding everything around it.

js

Traversal: parentElement, children, nextElementSibling

Move around the tree relative to an element you already have, instead of querying from scratch.

js

closest() — find a matching ancestor

Walks UP the tree from an element until it finds one matching a selector — perfect inside a delegated event handler.

js

Toggling visibility with .hidden

The hidden property is a clean boolean on/off switch — simpler than juggling style.display strings.

js

Building a table from real data

The pattern behind almost every data-driven UI: loop over an array, create a row per item, append it.

js

Reading form values

input.value for text, checkbox.checked for booleans — the two properties behind almost every form read.

09

Events

Making a page react to a person — clicks, typing, hovering. Try interacting with the little demos below; they're really listening. Sixteen examples — the most practical section on this whole page.

addEventListener basics

Attach a function to run whenever a specific event happens on an element — click the button below for real.

js

The event object & e.target

Every handler receives an event object — e.target tells you exactly which element triggered it.

js

Event delegation

One listener on the parent handles clicks on any current OR future child — far more efficient than one listener per item.

js

preventDefault()

Stops the browser's default action for an event — like a form reloading the page on submit.

js

Keyboard events

keydown fires on every key press — e.key tells you exactly which key.

js

Mouse events — enter / leave

mouseenter/mouseleave fire once per hover, unlike mouseover/mouseout which also fire for child elements.

js

Multiple listeners, one element

Every listener attached fires, in the order it was added — they don't replace each other like onclick= would.

js

removeEventListener

Needs a reference to the ORIGINAL function — this is exactly why inline arrow functions can't be removed later.

js

{ once: true }

Tells the browser to remove the listener automatically right after it fires the first time — no manual cleanup needed.

js

Bubbling & stopPropagation

A click on a child also fires its ancestors' click handlers by default — stopPropagation() is how you opt out.

js

Custom events

Dispatch your own named event with CustomEvent — the standard way for unrelated pieces of code to talk without calling each other directly.

js

input vs. change

input fires on every keystroke; change only fires once you commit the value (usually by clicking away).

js

Debouncing an input event

Cancel and reschedule a timer on every keystroke — the real code behind a search box that doesn't fire on every letter.

js

focus / blur

Fire when an element gains or loses keyboard focus — the basis of live field-level validation styling.

js

dblclick & contextmenu

Two events people forget exist — double-click, and intercepting the right-click menu.

js

Capstone: click + keyboard together

A counter driven by both a button and the keyboard — combining everything from this section into one small real widget.

10

Asynchronous JavaScript

JavaScript runs one thing at a time — this is how it still handles waiting on a timer, a server, or a file without freezing.

setTimeout — the building block

Doesn't pause anything. It schedules code to run later while everything else keeps going.

js

Callbacks

The original pattern: pass a function to be called once the async work finishes.

js

Promises

An object representing a value that will exist eventually — .then() for success, .catch() for failure.

js

async / await

Lets asynchronous code read top-to-bottom like synchronous code — the modern default over .then() chains.

js

Promise.all — run things in parallel

Waits for every promise to finish, but they all run AT THE SAME TIME instead of one after another.

js

Simulated fetch with error handling

The real shape of almost every API call you'll write — try/catch around an await.

11

Error handling

Real programs fail in expected ways. This is how you catch that on purpose, instead of letting the whole thing crash.

try / catch

Code in try runs normally; if it throws, execution jumps straight to catch instead of crashing the whole script.

js

finally

Runs no matter what — whether the try block succeeded, failed, or even returned early. Perfect for cleanup.

js

Custom error classes

Extend the built-in Error class to create your own error types, carrying whatever extra detail you need.

js

Throwing errors on purpose

throw immediately stops the current function and hands control to the nearest catch — your code decides what counts as an error.

js

Error handling in async code

try/catch works around await exactly like it does around synchronous code — the same mental model, no special cases.

js

Defensive validation

Check your assumptions about input EARLY and throw a clear message — much easier to debug than a confusing crash three functions later.

Classes & modern JS

The syntax for organizing related data and behavior together — and the features that make it genuinely safe to use.

Class basics

A blueprint for creating objects that share the same shape and behavior — constructor sets up each new instance.

js

Inheritance with extends

A subclass gets everything the parent has, and can override just the parts that need to differ.

js

Getters & setters

get/set let a property read like data but run real logic behind the scenes — including validation on write.

js

Static methods

Called on the class itself, never on an instance — for utility functions that logically belong to the class.

js

Private fields (#)

A # prefix makes a field truly inaccessible from outside the class — not just a naming convention, actually enforced.

js

Polymorphism

Different classes responding to the same method call, each in their own way — the payoff of a shared parent class.
