00

The mindset before the syntax

Programming is not remembering keywords. It's three actions, repeated in order, forever. Every system below — Django, infrastructure scripts, agents, pipelines — is just this loop applied to a real problem.

1. Hold data

Numbers, text, lists of things, labeled information — a user, a server, a price, a status.

2. Make decisions

Based on that data — if this, do that; otherwise, do something else.

3. Repeat & package

Do the same action for every item, and wrap useful actions into functions you reuse.

The actual goal

Never "write advanced Python." Always "solve a real problem cleanly." Everything below trains that, not trivia.

What a variable actually is

Think of a variable as a labeled box. age = 28 doesn't mean "age equals 28" like in math — it means "put the value 28 into a box, and label that box age." From then on, writing age anywhere means "go look inside that box." The = sign is Python's assignment operator: value on the right, box name on the left, always in that direction.

print vs return — a common early confusion

print() only displays a value on screen — nothing is saved. return hands the value back to the code that called the function, so it can be stored in a variable and used later. A function without return gives back None by default.

Rules for good functions

Do one thing. Have a name that says exactly what it does. Prefer return over only print, so other code can actually use the result — a function that only prints can't be reused inside a bigger program.

Default parameter values

Give a parameter a fallback value with = — the caller can leave it out entirely, or override it when they need something different. This is how real functions stay flexible without needing five variations of the same name.
